# План управления рисками

## Риски
R1. Связанность моделей данных разных доменов в DWH
- Использование методов DDD: выеделение bounded context, перенос хранилищ в домены владеющие ими.  
- Локальные копии данных внешних доменов через потоки событий.
- Остановка расширения DWH, CDC в домены до полной миграции

R2. Различные требования сертификации ПО/Процессов в разных регионах 
- Общение доменов и Платформы данных по независимым от реализации контрактам
- Использование в целевом регионе облачной инфраструктуры, соответствующей местной нормативной базе

R3. Внутренняя бизнес-логика доменов находится в ESB, которую планируется вывести из эксплуатации
- Составление Data Flow Diagram и инвентаризация маршрутов/трансформаций
- На время миграции - разделение центрального ESB на доменные части и размещение их в границах соответствующих доменов; постепенный перенос логики в доменные сервисы и на доменные события (Kafka); вывод из эксплуатации локального ESB домена по мере завершения миграции потоков.
- Разбиение функций ESB:
  - ФЛК/валидация - внутренняя логика доменов + Schema Registry; 
  - потоковые трансформации - Flink и Kafka Connect; 
  - пакетные трансформации - Spark; 
  - маршрутизация - Kafka (topics, consumer groups); 
  - паттерны надёжности - Kafka + DLQ + идемпотентные потребители; 
  - интеграционная логика - ACL в домене-потребителе; 
  - бизнес-логика - доменные сервисы внутри Bounded Context

R4. Бизнес-логика доменов завязана на другие домены через ESB, которую планируется вывести из эксплуатации
- Event-driven architecture: общение через события, ограничение синхронных вызовов между системами
- Использование методов DDD: выделение bounded context, ACL, data ownership

R5. Сопротивление изменениям сотрудниками
- Вовлечение пользователей платформы в процесс миграции в качестве стейкхолдеров
- Обучение сотрудников

R6. Утечка PII/PHI/чувствительных данных из доменов
- Домены должны фильтровать чувствительные данные перед отправкой
- Фиксированные схемы данных
- Анализ данных, классификация и Фильтрация на уровне платформы на этапе формирования Silver слоя
- Ограничение и аудит доступа к Bronze слою
- Gold/Витрины без PHI/PII

R7. Трудности миграции существующей отчётности на новую платформу
- Параллельный запуск 2 систем с постепенной миграцией
- Для критичной отчётности автоматизированная сверка результатов

R8. Доменные сервисы в разных регионах приводят к трансграничной передаче данных и соответствующим нормативным требованиям
- Создание локальных окружений Платформы данных 
- Обработка данных локализованно, получение бизнес-инсайтов и последующая передача агрегированных/анонимизированных данных в основную систему

R9. Отсутствие технической квалификации у персонала
- Обучение персонала
- Найм под целевую архитектуру
- Внешний консалтинг

R10. Неустоявшаяся регуляторная база для ИИ-сервисов
- Обособление доменов и коммуникация через чётко определённые события
- Возможность генерации внутренней отчётности внутри домена

R11. Нарушение контракта доменами
- Реестр схем для контроля схем данных
- Алёртинг при обнаружении нарушений
